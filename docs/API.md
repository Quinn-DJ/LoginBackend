# TastyMap API Contract

All endpoints are served under `https://<TASTYMAP_DOMAIN>`.

## Authentication

Public account creation is disabled. Create the first app user through the
server-side provisioning command after creating a PocketBase superuser.

Login:

```http
POST /api/collections/users/auth-with-password
Content-Type: application/json

{
  "identity": "user@example.com",
  "password": "..."
}
```

The response contains a PocketBase auth token. Send it on authenticated
requests:

```http
Authorization: <token>
```

The Apple client must persist the token in Keychain and discard it after a
`401`.

Refresh an existing token before expiry:

```http
POST /api/collections/users/auth-refresh
Authorization: <token>
```

Replace the Keychain token with the returned `token` value. Logging out is
client-side: delete the token from Keychain and clear in-memory auth state.

## Place Data

The `places` collection accepts these fields:

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `owner` | relation | yes | Current user record ID |
| `client_id` | text | yes | Stable UUID generated by the Apple client |
| `name` | text | yes | Store name |
| `address` | text | no | Street address |
| `latitude` | number | yes | -90 through 90 |
| `longitude` | number | yes | -180 through 180 |
| `category` | text | no | Cuisine or venue category |
| `tags` | JSON array | no | Searchable tags |
| `note` | text | no | Personal note |
| `status` | select | yes | `want_to_go`, `visited`, or `favorite` |
| `rating` | number | no | 0 through 5 |
| `client_updated_at` | date | yes | Last local edit time |
| `deleted` | bool | no | Soft-delete tombstone |
| `last_device_id` | text | no | Last client installation ID |

PocketBase adds `id`, `created`, and `updated`. The server-managed `updated`
field is the synchronization cursor and must not be replaced with a client
clock.

## Endpoints

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` | `/api/health` | Public health check |
| `POST` | `/api/collections/users/auth-with-password` | Login |
| `POST` | `/api/collections/users/auth-refresh` | Refresh an auth token |
| `GET` | `/api/collections/places/records` | List only the current user's places |
| `POST` | `/api/collections/places/records` | Create a place |
| `PATCH` | `/api/collections/places/records/:id` | Update a place |

Hard deletion is disabled for app users. A client deletion sets `deleted` to
`true` and updates `client_updated_at`, preserving a tombstone for other
devices.

`owner` must match the authenticated user. The unique index on
`(owner, client_id)` makes upload retries idempotent.

## Incremental Pull

The Apple client stores the highest `updated` value it has processed, then
requests:

```http
GET /api/collections/places/records?sort=updated&filter=updated%3E%22CURSOR%22
```

PocketBase automatically applies the collection list rule, so each user only
receives their own records. Include soft-deleted records in the pull and apply
their tombstones locally before removing them.

## Error Handling

- `400`: invalid field values or a duplicate `client_id`.
- `401`: missing or expired auth token.
- `403`: unauthenticated access, cross-user access, or an attempt to hard
  delete a place.
- `404`: the requested record does not exist or is not visible to the user.
- `429`: login or API rate limit.

Pull and push operations are safe to retry. Clients should retain local edits
until a successful response is persisted locally.
